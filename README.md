> 地球地面发射台发送指令（任务）给卫星，去指定位置拍摄月亮
>
> 卫星接收后通过红外、可见光、紫外线、光谱等信息运行到指定位置，调整相机载荷观测月亮（客户说 2° 以内的俯仰角？），观测完成后返回月亮图片

## 二、总体结论

**动画演示：可做。** 纯网页动画（Canvas / SVG / WebGL / GSAP 均可实现），**无技术门槛**。真正的难点不在编程，而在"**像不像真的**"——即动画里的动作序列、时序、数据标注是否符合航天工程常识。本文档的主要内容就是把每一步的**真实动作序列**写出来，动画照此演出即可具备专业感。

**真实业务能力分三级**：✅ 成熟技术（业界已有大量在轨应用）、⚠️ 需专项开发（路线清晰但需专门研制）、❌ 前沿研究（业界仍在探索）。

| 场景 | 动画 | 真实业务 | 关键结论 |
|---|---|---|---|
| 1 拍摄月亮 | 可做 | ✅ 成熟 | **不需要变轨**，靠可见性窗口 + 姿态指向；2° 约束来自**相机视场**，而非姿控能力 |
| 2 轨道异常自主规避 | 可做 | ❌ 部分前沿 | **卫星可以变轨**（规避机动是常规操作）；但**星上全自主**探测—决策—规避闭环仍属前沿 |
| 3 拍摄地面标记物 | 可做 | ✅ 成熟 | 需**轨道预报算过境时刻**；单星受**重访周期**限制，不能随时到访 |
| 4 图像回传 | 可做 | ✅ 成熟 | 受**地面站可见窗口**限制，**不能实时下传** |

## 三、场景 1 · 拍摄月亮

### 3.1 客户描述
地面发送指令，卫星"运行到指定位置"，调整相机载荷观测月亮（俯仰角 2° 以内），观测完成后返回月亮图片。

### 3.2 可行性

| 维度 | 结论 |
|---|---|
| 动画实现 | ✅ 可做，无难点 |
| 真实业务 | ✅ 成熟技术（对月成像 / 月球定标是遥感卫星的常规操作，月球常被用作辐射定标源） |

> **技术澄清一：拍摄月亮不需要变轨。**
> 月球距地约 38.4 万公里，卫星在 500 km 轨道上无论位于轨道何处，月球都在其视野范围内——**唯一需要做的是把星体姿态转过去，让相机对准月球**，轨道位置基本不用改。
>
> 真正制约"能不能拍到"的是两件事：
> **① 可见性**——地球会遮挡，卫星到地心距离约 6878 km，地球角半径约 67.9°，即月球方向若落入以"天底"为中心 67.9° 的锥内就被挡住，粗略估算约 **1/3 的时间月球被地球遮挡**，需等可见窗口；
> **② 太阳规避**——相机不能对着太阳方向，否则会烧毁探测器，需避开强光角度。

> **技术澄清二：关于 2° 俯仰角。**
> 这个约束的合理来源是**相机视场（FOV）**——指向误差须小于视场半角，否则目标会偏出画面。就姿控能力而言，2° 是**相当宽松**的要求：星敏感器定姿精度可达**角秒级**（1 角秒约 0.00028°），现代卫星姿态指向精度通常**优于 0.1°**。
>
> 换句话说：**2° 的难点不在"能不能转这么准"，而在于"相机视场有多窄"**。若相机视场窄于 2°，2° 的误差反而会拍空。

### 3.3 卫星动作序列

1. **指令接收与校验**：地面站上注任务指令 → 星务计算机校验合法性 → 排入任务队列
2. **状态自感知**：读取自身轨道位置与速度 → 读当前姿态（星敏 + 陀螺）→ 读电源状态（确认供电充足）
3. **目标方位解算**：查月球星历（简化月球历表即可）→ 算出月球在惯性系的方向 → 转换到星体系 → 得目标姿态
4. **可见性判断**：判断月球方向是否被地球遮挡 → 判断与太阳夹角是否安全（规避太阳）→ 不在窗口则等待
5. **姿态机动（Slew）**：规划最短角距转动路径 → 飞轮输出力矩 → 星体三轴旋转 → 粗指向到位
6. **精指向与稳定**：星敏精定姿 → 姿态闭环微调 → 指向误差收敛（优于 0.1°）→ 姿态稳定
7. **相机开机与成像**：相机加电自检 → 自动测光（月球很亮，需短曝光防过曝）→ 按曝光参数成像 → 可多帧连续拍摄
8. **数据存储**：图像压缩 → 存入星上固态存储器 → 记录成像时刻、姿态、曝光参数等辅助数据
9. **数据回传**：等待地面站可见窗口 → 建链 → 下传图像（详见场景 4）

### 3.4 数据采集

| 类别 | 具体内容 |
|---|---|
| **星上测量数据** | 轨道位置速度（GPS / 定轨）、姿态角（星敏 + 陀螺）、角速度、太阳方向（太敏） |
| **载荷图像数据** | 月球图像（可见光为主）、曝光时间、增益、成像时刻、相机温度 |
| **平台状态数据** | 电源母线电压 / 电流、电池 SOC、各分系统健康状态（温度、电压、模式） |
| **辅助数据** | 卫星位置、姿态四元数、载荷指向角（供地面做图像几何校正） |

### 3.5 任务分解（自感知 · 自决策 · 自执行）

| 环节 | 具体步骤 |

| **自感知** | ① 取自身轨道位置与速度　② 读当前姿态与角速度　③ 查月球星历算月球方位　④ 判断可见性（地球遮挡、太阳夹角） |

## 四、场景 2 · 轨道异常目标自主规避

### 4.1 客户描述与建议调整

**客户原描述**：发现轨道上有异物，自主决策，调整姿态等躲避异物。

**建议演示方案（更贴合工程实际）**：模拟**一颗报废卫星（或空间碎片）沿轨道接近**，卫星自主完成 **识别 → 计算 → 变轨 → 恢复** 的完整闭环：

| 环节 | 动画表现 |
|---|---|
| **自主识别** | 星载探测载荷发现接近目标 → 多帧跟踪 → 判别为报废卫星 / 碎片 |
| **计算** | 外推双方轨迹 → 计算最近接近时刻与最小距离 → 评估碰撞概率 → 规划规避方案 |
| **变轨** | 姿态调整使推力轴对准 → 推力器点火施加 Δv → 轨道抬升 / 降低，双方安全错开 |
| **恢复** | 风险解除后，择机施加反向小 Δv → 返回标称轨道 → 恢复正常任务 |

### 4.2 可行性

| 维度 | 结论 |
|---|---|
| 动画实现 | ✅ 可做（视觉演出效果很好，是全片亮点） |
| 真实业务 | **分两段看：**<br/>· **变轨规避本身** —— ✅ 成熟技术，属常规在轨操作<br/>· **星上全自主**（探测 + 定轨 + 决策闭环）—— ❌ 前沿研究，业界尚无普及方案 |

> **技术澄清一：卫星可以变轨。**
> 通常说的"轨道已经预定好"指的是**标称轨道**（设计时确定的理想轨道）；但实际飞行中，卫星**必须主动机动**：
>
> **① 轨道会持续受扰动**——大气阻力、地球非球形引力（J2 项）、太阳光压等，不修正就会逐渐偏离；
> **② 轨道保持是常规操作**——地球同步轨道卫星需定期做南北 / 东西保持；低轨卫星需持续克服大气阻力造成的轨道衰减；
> **③ 规避机动是常态**——国际空间站每年执行多次碎片规避；大型低轨星座的卫星每年做多次自主避碰。
>
> 因此"接近目标 → 自主计算 → 变轨规避 → 返回标称轨道"是**符合工程实际的完整闭环**，可以放心作为演示内容。

> **技术澄清二：唯一的硬约束是燃料。**
> 变轨依靠**推进剂**，消耗完卫星就"定型"了。因此真实规避都是**小幅微调**：
>
> 典型规避只需 **0.1 ~ 1 m/s** 的速度增量 Δv，提前**数十分钟到数小时**执行，就能把交会距离拉开到安全值——**不是大幅变轨**。规避完成后，可视任务需要再施加一次**反向小 Δv 返回标称轨道**（即演示中的"恢复"环节）。

> **🚨 必须指出的一处物理问题：仅靠调整姿态不能实现避碰。**
> 碰撞是**两个轨道是否交会**的问题，而姿态改变的是星体朝向、**不改变轨道（质心运动）**。姿态调整只能通过改变迎风截面积、长期微弱影响大气阻力，**对短期碰撞规避没有实际作用**。
>
> 正确做法：**姿态调整是变轨的前置动作**——先把推力轴对准所需方向，再由推力器点火变轨。**动画可保留"星体转动"演出，但文字框应写"规避机动（变轨）"**。

### 4.3 卫星动作序列

1. **异常目标感知**：星载探测载荷（雷达 / 光学）发现接近目标，或接收地面空间编目预警 → 触发告警
2. **目标识别与跟踪**：连续多帧跟踪测量 → 提取方位、亮度与运动信息 → 判别目标类型（报废卫星 / 碎片）→ 估计其轨道
3. **交会计算**：结合自身精密定轨结果 → 外推双方轨迹 → 计算最近接近时刻（TCA）、最小距离与相对速度 → 评估碰撞概率
4. **规避决策**：判断碰撞概率是否超阈值 → 选择机动策略（轨道抬升 / 降低 / 提前 / 延后）→ 计算最小 Δv 方案 → 确定点火时刻与推力方向
5. **变轨执行**：姿态机动使推力轴对准所需方向 → 推力器点火，施加 Δv → 轨道改变，与目标安全错开
6. **效果确认**：重新外推轨道 → 确认最小距离已大于安全门限 → 解除告警
7. **轨道恢复**：择机施加反向小 Δv → 返回标称轨道 → 恢复正常在轨任务
8. **记录与上报**：生成规避事件报告（含探测、计算、机动全过程数据）→ 等地面站窗口下传复核

### 4.4 数据采集

| 类别 | 具体内容 |
|---|---|
| **目标探测数据** | 目标方位角、俯仰角、亮度、运动角速度、时序测量序列（用于目标定轨） |
| **自身轨道数据** | 自身位置、速度矢量（精密定轨结果，其精度直接决定交会计算准确度） |
| **交会计算结果** | 最近接近时刻 TCA、最小距离、相对速度、碰撞概率 Pc |
| **机动参数** | 所需 Δv 大小与方向、点火时刻与时长、预计推进剂消耗、机动后轨道根数 |
| **恢复参数** | 标称轨道参数、当前轨道偏差量、恢复所需反向 Δv、恢复时机 |
| **状态监控** | 推力器状态、推进剂余量、电源功率、姿态稳定度 |

### 4.5 任务分解（自感知 · 自决策 · 自执行）

| 环节 | 具体步骤 |
|---|---|
| **自感知** | ① 探测发现接近目标（报废卫星 / 碎片）　② 多帧跟踪提取方位与运动　③ 判别目标类型并估计其轨道　④ 自身精密定轨　⑤ 外推双方轨迹并计算交会几何与碰撞概率 |
| **自决策** | ① 判断 Pc 是否超安全阈值　② 评估规避必要性　③ 选择机动策略（抬升 / 降低 / 提前 / 延后）　④ 计算最小 Δv 方案（省燃料）　⑤ 确定点火时刻与推力方向　⑥ 校验推进剂与电源余量　⑦ 规划轨道恢复方案 |
| **自执行** | ① 姿态机动：把推力轴对准所需方向　② 推力器点火，施加 Δv　③ 机动结束姿态恢复　④ 重新定轨确认风险解除　⑤ 择机施加反向 Δv 返回标称轨道　⑥ 更新轨道参数并上报 |
| **数据与告警** | 记录探测 / 计算 / 机动全过程 → 生成规避报告 → 下传地面（地面站独立复核） |

### 4.6 步骤框文本（动画可直接使用）

```
【异常感知】星载探测 / 地面预警发现接近目标（报废卫星）→ 多帧跟踪 → 判别目标类型与轨道
【自感知】自身精密定轨 → 外推双方轨迹 → 计算最近接近时刻、最小距离与碰撞概率
【自决策】碰撞概率超阈值 → 选择规避策略 → 计算最小 Δv 与点火时刻 → 校验推进剂余量 → 规划恢复方案
【自执行】姿态机动使推力轴对准方向 → 推力器点火施加 Δv → 轨道抬升 / 降低 → 重新定轨确认风险解除
【轨道恢复】择机施加反向小 Δv → 返回标称轨道 → 生成规避报告并下传地面
```

### 4.7 未来能否真实落地

| 能力项 | 落地判断 | 说明 |
|---|---|---|
| 地面编目 + 交会预警 | ✅ 成熟 | 现有航天测控体系的标准业务 |
| 规避机动（变轨） | ✅ 成熟 | 需卫星具备推进能力与足够推进剂；国际空间站、大型星座均常态执行 |
| 轨道保持与恢复 | ✅ 成熟 | GEO 卫星南北 / 东西保持即属此类，常规操作 |
| 星载空间目标探测与识别 | ⚠️ 需专项开发 | 需雷达或光学探测载荷，受体积、功耗、算力限制 |
| 星上自主定轨与交会计算 | ⚠️ 需专项开发 | 需星上高精度轨道外推能力 |
| 星上全自主避碰闭环 | ❌ 前沿研究 | 无需地面干预的完整闭环，业界仍在探索（现有自主避碰仍主要依赖地面编目上行） |
| 仅靠姿态调整避碰 | ❌ 物理不成立 | 姿态不改变质心轨道，无法规避碰撞 |

## 五、场景 3 · 拍摄美国上空标记物

### 5.1 客户描述
地面发送指令，去美国上空拍摄标记物；卫星"自主决策飞行，调整姿态"；到达上空后调整姿态拍摄。

### 5.2 可行性

| 维度 | 结论 |
|---|---|
| 动画实现 | ✅ 可做 |
| 真实业务 | ✅ 成熟技术（遥感卫星成像任务规划是标准业务，全球主要遥感卫星都具备） |

> **关键约束：单星不能"随时到访"。**
> 低轨（500 km）卫星对同一地面点的**重访周期**通常为**数小时到数天**，取决于轨道倾角、回归特性与侧摆能力。所谓"去美国上空"，工程上是：① 用**轨道预报**算出卫星何时经过目标附近；② **等待**到过境时刻；③ 在过境前后**调整姿态（含侧摆）**对准目标成像。
>
> **关于侧摆（Roll）**：卫星可通过横滚侧摆观测星下点两侧的目标，扩大可观测范围，但代价是**斜距增大、分辨率下降**。

### 5.3 卫星动作序列

1. **指令接收与解析**：接收地面任务（目标经纬度、拍摄要求）→ 校验 → 入任务队列
2. **目标可见性预报**：用轨道预报模型外推未来轨道 → 计算目标何时进入可观测范围 → 确定过境时刻
3. **任务规划**：结合多目标优先级、电源余量、存储余量、数传窗口 → 排出成像计划
4. **等待与姿态预置**：到达过境前若干分钟 → 姿态预转向目标方向（预置可减小机动量）
5. **对地指向**：按过境几何解算指向姿态（星下点或侧摆）→ 姿态机动 → 精指向稳定
6. **成像**：相机按计划成像 → 按条带推扫或定点凝视 → 多帧 / 多光谱采集
7. **存储与下传**：图像压缩存储 → 等地面站窗口下传（详见场景 4）

### 5.4 数据采集

| 类别 | 具体内容 |
|---|---|
| **轨道与时间** | 星上时间、轨道位置速度、星下点经纬度、过境时刻预报 |
| **姿态数据** | 姿态四元数 / 欧拉角、角速度、指向角（含侧摆角） |
| **图像数据** | 目标区域图像（可见光 / 多光谱）、成像时刻、曝光参数、条带编号 |
| **质量辅助数据** | 相机温度、平台稳定度（姿态角速度）、太阳高度角 |

### 5.5 任务分解（自感知 · 自决策 · 自执行）

| 环节 | 具体步骤 |
|---|---|
| **自感知** | ① 取轨道位置速度　② 读当前姿态　③ 读目标点经纬度（来自指令）　④ 读电源、存储余量 |
| **自决策** | ① 轨道预报算过境时刻　② 计算可观测窗口与侧摆角　③ 多任务优先级排序　④ 排定成像时序与曝光参数　⑤ 关联最近地面站窗口 |
| **自执行** | ① 姿态预置 → 对地指向机动　② 精指向稳定　③ 按计划成像（推扫 / 凝视）　④ 压缩存储并打标签 |
| **数据回传** | 等待地面站窗口 → 按优先级下传 |

### 5.6 步骤框文本（动画可直接使用）

```
【指令接收】地面站上注任务：拍摄美国上空标记物（含目标经纬度）
【自感知】取轨道位置速度 · 读当前姿态 · 解析目标点坐标 · 读电源与存储余量
【自决策】轨道预报算过境时刻 · 计算可观测窗口与侧摆角 · 多任务优先级排序 · 排定成像时序
【自执行】姿态预置 → 对地指向机动 → 精指向稳定 → 按条带成像 → 压缩存储并打标签
【数据回传】关联最近地面站窗口 → 按优先级下传图像
```

### 5.7 未来能否真实落地

| 能力项 | 落地判断 | 说明 |
|---|---|---|
| 星上轨道预报 | ✅ 成熟 | 常用简化模型，算力需求低 |
| 过境时刻计算 | ✅ 成熟 | 常规功能 |
| 三轴对地指向 + 侧摆 | ✅ 成熟 | 成熟姿控功能 |

## 六、场景 4 · 图像数据回传

### 6.1 客户描述
到达美国上空，调整姿态拍摄，并传回图片数据。

### 6.2 可行性

| 维度 | 结论 |
|---|---|
| 动画实现 | ✅ 可做 |
| 真实业务 | ✅ 成熟技术（测控与数传是卫星标配） |

> **关键约束：数传不能实时进行。**
> 卫星必须**飞到地面站上空**（进入地面站可见范围）才能建立下行链路。低轨卫星单次过境某地面站的可见时间通常仅 **5~10 分钟**，而一次成像的数据量可能很大。
>
> 因此：图像先**存在星上固态存储器**里；等到**地面站窗口**再下传；需在**数据量、下行速率、窗口时长**之间平衡，必要时做星上压缩、分优先级下传（重要图像先传）。

### 6.3 卫星动作序列

1. **数据就绪**：图像压缩打包 → 附加辅助数据（时刻 / 姿态 / 参数）→ 存入星上存储器
2. **窗口预报**：计算下一可见地面站与过境时刻 → 准备建链
3. **建链**：卫星进入地面站可见范围 → 测控链路建立 → 数传链路建立
4. **数据下传**：按优先级下传图像与遥测 → 地面站接收 → 校验完整性 → 未收全则重传
5. **收尾**：下传完成确认 → 释放存储空间 → 记录数传日志

### 6.4 数据采集

| 类别 | 具体内容 |
|---|---|
| **下行数据** | 图像文件、辅助数据（姿态 / 时刻 / 参数）、平台遥测（电压 / 温度 / 模式 / 健康状态） |
| **链路参数** | 下行速率、误码率、链路余量、接收信号强度 |
| **状态数据** | 存储器余量、下传进度、未传数据队列 |

### 6.5 任务分解（自感知 · 自决策 · 自执行）

| 环节 | 具体步骤 |
|---|---|
| **自感知** | ① 监测存储器余量与数据队列　② 计算下一地面站可见窗口　③ 监测链路状态与天线指向 |
| **自决策** | ① 制定下传计划（优先级排序）　② 选择下行速率与调制方式　③ 决定是否需要星上压缩或降分辨率　④ 冲突时取舍（成像 vs 下传） |
| **自执行** | ① 姿态调整使数传天线对准地面站　② 建立测控 / 数传链路　③ 分优先级下传　④ 校验完整性并重传　⑤ 释放存储空间 |
| **地面协同** | 地面站接收 → 解调译码 → 数据校核 → 分发给用户 |

### 6.6 步骤框文本（动画可直接使用）

```
【数据就绪】图像压缩打包 · 附加辅助数据（成像时刻 / 姿态 / 曝光参数）· 存入星上存储器
【自感知】监测存储余量与待传队列 · 预报下一地面站可见窗口 · 监测链路状态
【自决策】制定下传计划（按优先级排序）· 选择下行速率 · 必要时星上压缩或降分辨率
【自执行】姿态调整使数传天线对准地面站 → 建立数传链路 → 按序下传 → 校验重传 → 释放存储
【地面接收】地面站接收解调 · 数据校核 · 分发给用户
```

### 6.7 未来能否真实落地

| 能力项 | 落地判断 | 说明 |
|---|---|---|
| 星上存储 | ✅ 成熟 | 固态存储器，标准配置 |
| 图像压缩 | ✅ 成熟 | 常规功能 |
| 测控 / 数传链路 | ✅ 成熟 | 标准分系统 |

## 七、任务分解机制设计（客户核心诉求）

客户要求的核心是"卫星接收指令后，按**自感知、自决策、自执行**的内核完成任务分解"。这是一套**自主任务管理架构**，建议按下表设计（三级能力递进）：

| 级别 | 名称 | 特征 | 典型功能 | 真实实现难度 |
|---|---|---|---|---|
| **L1** | 地面主导 | 地面规划好指令序列，星上按时执行 | 定时成像、姿态机动、数据下传 | ✅ 当前业界主流 |
| **L2** | 星上辅助 | 星上具备局部自主能力 | 自主定姿、自主健康管理、异常自主安全模式、自主测光 | ✅ 已广泛实现 |
| **L3** | 星上自主 | 星上完成感知-决策-执行闭环 | 自主任务规划、自主目标识别、自主避碰 | ⚠️~❌ 部分前沿 |

> **📌 动画中的呈现建议：** 将每个场景的步骤框按 **【自感知】→【自决策】→【自执行】→【数据回传】** 四段展示，并加一个"能力标注"角标：
> · 场景 1（拍月亮）、场景 3（拍地面标记物）、场景 4（数据回传）标注 **L2 星上辅助**
> · 场景 2（轨道异常自主规避）标注 **L3 星上自主（前沿方向）**
>
> 这样既能满足客户"看到任务分解"的要求，又能**如实反映技术成熟度**，避免给客户造成"这些都已经能做了"的误解。

**任务分解的通用内核（动画文字框可复用）：**

```
【指令接收】地面站上注任务 → 星务校验 → 入任务队列
【自感知】读自身状态（轨道 / 姿态 / 电源 / 存储）→ 感知外部环境（目标方位 / 可见性 / 威胁）
【自决策】解算目标 → 规划动作序列 → 评估约束（电源 / 热控 / 时间 / 燃料）→ 排定时序
【自执行】按序列驱动分系统（姿控 / 载荷 / 推进 / 数传）→ 执行并监控
【数据回传】记录数据 → 等地面站窗口 → 下传 → 地面复核
```

## 八、星载算力与端侧推理需求

客户明确提出："**星载计算机肯定要带算力的，才能具备端侧推理**"。这个判断**方向上正确**，但需要按环节区分——并非所有功能都需要高算力。

| 功能环节 | 算力需求 | 硬件选型方向 |
|---|---|---|
| 时统、遥测采集、指令分发 | 极低 | 普通 MCU |
| 轨道预报、姿态解算、控制律 | 低 | 抗辐照 MCU / 低端 ARM |
| 姿态确定（星敏星图匹配） | 低 | 传统算法即可在抗辐照处理器上运行（**真实星敏正是这么做的，不需要 AI**） |
| 激光 / 光学目标检测（点目标提取） | 中 | 中端 ARM / DSP（经典图像处理算法） |
| **图像目标识别（AI 端侧推理）** | **高** | **NPU / GPU / FPGA 加速的载荷处理机**——这才是"端侧推理"的真正需求场景 |
| **星载空间目标探测 + 自主定轨** | **最高** | 高性能载荷处理机 + 专用加速 |

> **🚨 关键区分（务必对客户讲清）：**
>
> **任务规划、姿态解算、星图匹配**这类算法是**传统数学 / 信号处理算法**，算力需求低，普通星载计算机即可胜任，**不需要端侧推理**。
>
> 只有**图像内容识别**（如识别地面目标类型、识别空间目标）才需要**深度学习推理**，需要带 NPU / GPU / FPGA 的高性能载荷处理机。星载 AI 还需配套**模型量化与剪枝**（压缩到星载算力可承载）、**抗辐照加固**、**功耗与散热设计**。
>
> **建议表述**：本演示中，**基础任务规划与姿态控制**用普通星载计算机即可实现；若要在星上做**图像内容识别与自主决策**，则需配置**带 AI 加速的载荷处理机**，这是需要专项研制的部分。
